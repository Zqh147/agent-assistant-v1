# 售后场景测试报告

更新日期：2026-10-14。当前为本地演示业务版本。

## 实现范围

订单与设备查询；版本化的演示售后规则；基于订单记录和日期的确定性资格判断；工单草稿、当前轮确认、幂等提交、状态与事件查询；按演示客户和创建会话校验对象归属；设备范围自动补齐与冲突拦截；SQLite 会话与业务上下文恢复；API UTF-8 响应。原有通用 Agent、MCP 计算 / 时间工具和 RAG 检索适配器保持不变。

## 验证结果

| 检查 | 结果 | 口径 |
|---|---|---|
| pytest 全部回归 | 通过（数量见 README） | 不调用真实生成模型 |
| 通用 Agent 验收 | 8/8 | 脚本模型选择工具，真实执行工具 |
| 售后流程离线验收 | 9/9 | 确定性离线规则；隔离 SQLite；产品检索使用夹具 |
| 售后流程 + 真实 RAG 服务 | 9/9 | 真实 Embedding / Chroma / BM25 / RRF / Reranker / HTTP；工具选择为离线规则 |
| 真实 HTTP 工单流程 | 10/10 | 真实 Uvicorn、HTTP 与 SQLite；Agent 决策为离线规则 |
| 停止并重启 Agent 进程 | 7/7 | 草稿恢复、确认提交、进度查询；只生成一张工单、一次提交事件 |
| 本地业务工具 + 真实 stdio MCP | 3/3 | 订单查询 `source=local`，计算 `source=mcp` |

运行环境：Linux，Python 3.12.14；langgraph 0.6.11、langchain-core 0.3.86、mcp 1.30.0、openai 1.109.1、pytest 8.4.2、fastapi 0.143.0、httpx 0.28.1。

## 覆盖的负例

他人订单、订单不存在、未交付、超出演示窗口、边界日期、用户未确认却请求提交、伪造客户或确认参数、跨会话提交、资格或规则版本变化、模型最终回复失败、检索设备参数冲突、旧会话表迁移、HTTP 模型失败时保留部分报告。

## 过程中发现的问题

首次接入真实检索时，把「订单查询 + 技术问题」整段作为检索 query 会降低匹配度。修正为技术 query 与订单指令分开，设备条件通过已验证的订单上下文传入。修正后真实检索接入 9/9 通过。
